# 智能井盖检测系统参赛 PDF 编写计划

## 1. 参赛定位

- 建议场景分类：智能终端。
- 项目名称：智能井盖检测系统。
- 作品形态：模块化硬件原型 + ESP32-S3 边缘固件 + M100PG Cat.1/GNSS 通信 + CloudBase 云端 + 维修人员 Web 工作台。
- 目标用户：市政井盖巡检人员、维修人员、道路设施管理单位。
- 核心问题：传统人工巡检发现不及时，井盖倾斜、移位、开启和井下水位风险缺少统一的实时监测、定位和告警闭环。
- 真实性表述：传感器及通信部分采用成熟采购模块，团队完成系统选型、接口电路、模块互联、嵌入式固件、多传感器风险判断、通信协议、云端接收、账号系统和可视化工作台。

## 2. 最终交付物

1. `智能井盖检测系统-应用方案.pdf`：建议 18 页，不超过 20 页。
2. `智能井盖检测系统-硬件设计说明.pdf`：建议 6～8 页，包含模块级原理图、接线表和 BOM。
3. `实物原型照片/`：整机、俯视、侧面、模块连接、井盖模拟场景、网页联动等多角度原始照片。
4. `演示视频.mp4`：控制在 5 分钟以内，必须录入真实硬件运行和公网网站画面。
5. 公网运行链接和可提交源码。

## 4. AI 部分的写作边界

当前倾角阈值、水位阈值和霍尔组合判断属于确定性算法，不能直接包装成 AI。为了满足赛事对 AI 核心作用的评分要求，应在提交前增加并真实演示“AI 维修研判助手”：

- 输入：倾角、水面净空、水面变化率、霍尔状态、定位、历史告警和设备在线状态。
- 输出：风险原因解释、紧急程度、建议携带工具、现场检查步骤、维修工单摘要。
- 安全边界：底层硬件报警仍由本地确定性规则完成，AI 只负责辅助研判和文本建议，不能覆盖安全报警。
- PDF 中必须展示真实接口、真实输入输出和演示截图；若未完成，不应写成已实现功能。

## 6. 模块拼接型硬件怎样画“电路原理图”

不需要抄画采购模块内部所有芯片电路，也不能把厂家模块内部设计写成自研。应绘制“模块级电气原理图”或“系统互联原理图”：

1. 将 ESP32-S3-N16R8 开发板画成主控模块方框，列出实际使用的 3V3、5V、GND 和 GPIO。
2. 将 MPU6050、US-100、左右霍尔模块、LED/蜂鸣器、M100PG 分别画成独立模块方框或连接器符号。
3. 画出每根信号线、供电线、公共地、通信方向和电平。
4. 对模块板载电路标注“模块内部已集成”，例如稳压、I²C 上拉、LM393 比较器或 M100PG 测试底板电源电路。
5. 自己增加的限流电阻、上拉电阻、三极管/MOSFET驱动、滤波电容和接口连接必须画清楚。
6. 图纸标题写“智能井盖检测终端模块级原理图（原型V1.0）”，不要写成自研 PCB 原理图。

### 6.1 推荐原理图分区

```text
电源输入
  ├─ ESP32-S3 开发板电源 → 3.3V传感器电源
  └─ M100PG Test-C/稳压电源 → M100PG核心板

ESP32-S3
  ├─ I2C → MPU6050
  ├─ TRIG/ECHO → US-100
  ├─ GPIO → 左/右霍尔模块
  ├─ GPIO/PWM → LED与蜂鸣器
  └─ UART1 → M100PG DTU

M100PG
  ├─ 4G天线
  ├─ GNSS天线
  └─ 内置SIM → 移动网络 → CloudBase
```

### 6.2 当前项目 GPIO 接线表

| 功能模块 | 模块端 | ESP32-S3 |
|---|---|---:|
| MPU6050 | SDA | GPIO8 |
| MPU6050 | SCL | GPIO9 |
| 倾角报警 LED | 信号 | GPIO2 |
| 倾角有源蜂鸣器 | 信号 | GPIO4 |
| US-100 | TRIG | GPIO16 |
| US-100 | ECHO | GPIO17 |
| 水位 LED | 信号 | GPIO5 |
| 水位无源蜂鸣器 | PWM信号 | GPIO6 |
| 左霍尔模块 | DO | GPIO7 |
| 右霍尔模块 | DO | GPIO10 |
| M100PG | RXD ← ESP32 TX | GPIO11 |
| M100PG | TXD → ESP32 RX | GPIO12 |
| 全部模块 | GND | 公共地 |

### 6.3 必须在图中标注的注意事项

- MPU6050 使用 3.3V I²C，地址默认 `0x68`，兼容 `0x69`。
- US-100 使用 Trig/Echo 模式，拔掉模式跳帽，当前按 3.3V 方案连接。
- 霍尔模块 DO 为数字输入，磁铁靠近时按当前程序定义为低电平有效。
- ESP32 TX 接 M100PG RXD，ESP32 RX 接 M100PG TXD，必须共地，UART 为 115200、8N1。
- ESP32 正式接管 M100PG UART 时，断开测试底板上连接 CH340 的 `M_TXD/M_RXD` 跳帽，避免两个发送端冲突。
- M100PG 的 4G 和 GNSS 天线均需正确连接，不能用信号线代替天线。
- M100PG 发射瞬间电流较大，供电应留出峰值余量；若仍使用 Test-C 底板，应将底板作为供电和接口模块如实画入原理图。
- 现阶段若 ESP32 与 M100PG 分别供电，也必须连接公共 GND，并在文档中按实物状态说明。

## 7. 原型电路与改进电路分开写

### 已实现原型

- 采购模块通过杜邦线/测试底板连接。
- ESP32 GPIO 直接读取 MPU6050、US-100 和霍尔模块。
- LED和蜂鸣器按当前实物接线驱动。
- M100PG 使用测试底板完成配置和通信验证。

### 建议下一版但尚未实施

- 为蜂鸣器增加 NPN 或逻辑级 MOSFET 驱动，GPIO 只提供控制信号。
- LED 增加明确的限流电阻。
- M100PG 电源附近增加大容量储能电容和 0.1uF 去耦。
- 接口增加反接、浪涌和静电保护。
- 设计统一转接底板或 PCB，使用锁紧端子代替杜邦线。
- 增加防水、防凝露、防腐蚀和电池低功耗设计。

文档中只能把“已实现原型”写为完成项；改进内容应放入局限性和后续计划。

## 10. 编写与验收顺序

1. 冻结参赛版本功能和硬件接线。
2. 补拍实物、连接和测试照片。
3. 使用 KiCad、嘉立创 EDA 或 DrawIO 绘制总体框图和模块级原理图。
4. 按实际购买记录建立 BOM。
5. 完成 AI 维修研判助手，或从主文档中删除未实现的 AI 表述。
6. 完成主应用方案初稿和硬件说明初稿。
7. 录制 5 分钟内的硬件与网站联动视频。
8. 核对所有参数、GPIO、阈值、网址和截图与实物一致。
9. 导出 PDF，检查页数、字体、图表清晰度和链接可访问性。
10. 最终提交前在另一台电脑和手机上验证公网网站。
