# ESP32-S3-CAM 照片采集上传项目计划书

## 0. 项目边界

本目录 `camera` 是 ESP32-S3-CAM 固件项目，负责摄像头、按键、Wi-Fi、HTTPS 上传、重试和设备日志等功能。

网站前端、网站后端和 CloudBase 资源不在本目录开发；相关需求通过《网站照片采集功能-交接实施方案.md》交给另一个网站项目实现。本项目只依赖双方确认后的设备 API，不复制网站源码，也不在这里搭建临时网页。

当前目录的最终交付应包括：

- 可编译、可烧录的 ESP32-S3-CAM 固件工程。
- OV2640 和物理按键配置。
- 连接电脑热点的配置方式。
- 连拍 3～5 张及 HTTPS 上传实现。
- 设备鉴权、失败重试、幂等序号和状态日志。
- 配置示例、烧录说明、联调说明和基础测试。

## 1. 项目目标

在现有“智慧井盖”网站的登录后管理界面中新增“照片采集”功能，并让 ESP32-S3-CAM（OV2640）完成以下闭环：

1. ESP32-S3-CAM 连接电脑开启的 Wi-Fi 热点。
2. 用户按下开发板上的指定物理按键。
3. 设备连续拍摄 3～5 张 JPEG 照片。
4. 照片通过 HTTPS 上传到网站对应的云端接口与对象存储。
5. 网站登录用户可以查看采集批次、照片、设备编号、采集时间和上传状态。

说明：照片不应直接“上传到网页”，而是上传到网站后端接口或腾讯云 CloudBase 云存储；网页从后端读取并展示照片。

## 2. 建议的 MVP 范围

第一版只实现一台设备、一个物理按键和基础照片列表，不加入实时视频、人脸识别、目标检测及远程控制。

- 设备联网：连接电脑热点，断线自动重连。
- 按键采集：一次按键触发一个批次，照片数量可配置为 3～5 张，默认 3 张。
- 拍摄间隔：默认 500 ms，可配置。
- 图片参数：JPEG、VGA（640×480）起步，质量参数 10～15。
- 上传机制：逐张上传；失败自动重试；同一批次使用统一 `batchId`。
- 网站功能：批次列表、照片缩略图、单图预览、状态筛选和手动刷新。
- 权限：照片页面仅对已登录用户开放；设备使用独立设备凭证，不能复用管理员账号密码。

## 3. 总体架构

```text
物理按键
   ↓
ESP32-S3-CAM + OV2640
   ↓  HTTPS（设备令牌 / HMAC 签名）
CloudBase HTTP 云函数或现有网站后端
   ├─ CloudBase 云存储：保存 JPEG
   └─ CloudBase 数据库：保存设备、批次和照片元数据
            ↓
登录后的智慧井盖管理网页
   └─ 照片采集页：列表、预览、状态与详情
```

电脑热点必须开启“共享互联网”，否则 ESP32 虽能连接热点，但无法访问公网云端接口。

## 4. 网站端接口依赖（由另一个项目实现）

### 4.1 登录后界面新增入口

在现有侧边栏或顶部导航增加“照片采集”菜单，路由建议为 `/photo-collection`。

页面建议包含：

- 顶部统计：今日采集批次、今日照片数、上传失败数、最近在线设备。
- 筛选区：设备编号、起止时间、上传状态。
- 批次列表：批次编号、设备编号、照片数量、采集时间、上传结果。
- 照片区：缩略图宫格、点击放大、原图查看。
- 状态提示：采集中、上传中、上传完成、部分失败、全部失败。

第一版不建议在网页上增加“远程拍照”按钮，因为当前需求是物理按键触发；这可作为第二阶段功能。

### 4.2 云端接口

建议提供以下接口：

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/device/heartbeat` | POST | 上报设备在线状态、IP 和固件版本 |
| `/api/photo-batches` | POST | 创建一个采集批次，返回 `batchId` |
| `/api/photo-batches/{batchId}/photos` | POST | 上传单张 JPEG 及序号 |
| `/api/photo-batches/{batchId}/complete` | POST | 标记批次上传结束并写入成功/失败数量 |
| `/api/photo-batches` | GET | 网站分页查询批次 |
| `/api/photo-batches/{batchId}` | GET | 查询某批次及照片列表 |

若照片直接经过云函数，需检查请求体大小和超时限制。更稳妥的正式方案是：设备先请求短时有效的上传地址，再将 JPEG 直传 CloudBase 云存储，最后提交照片元数据。

### 4.3 数据结构

`devices`：

- `deviceId`
- `name`
- `enabled`
- `secretHash`
- `lastSeenAt`
- `firmwareVersion`

`photo_batches`：

- `batchId`
- `deviceId`
- `requestedCount`
- `successCount`
- `failedCount`
- `status`
- `capturedAt`
- `completedAt`

`photos`：

- `photoId`
- `batchId`
- `deviceId`
- `sequence`
- `storageFileId` 或对象键
- `thumbnailUrl`
- `sizeBytes`
- `width`
- `height`
- `sha256`
- `capturedAt`

数据库只存元数据和对象存储标识，不直接保存图片二进制。

### 4.4 安全要求

- 全程 HTTPS，并在 ESP32 中校验证书；不要使用跳过证书校验的方式作为正式方案。
- 每台设备分配独立 `deviceId` 和密钥，密钥不写入前端代码或公开仓库。
- 请求携带时间戳、随机数和 HMAC 签名，服务端校验时间窗口，防止重放。
- 服务端限制文件类型、单张大小、单批数量和请求频率。
- 云存储默认私有；登录后由后端生成短时访问 URL。
- 管理员可禁用丢失或异常设备。

## 5. ESP32-S3-CAM 固件设计

### 5.1 模块划分

- `camera_config`：OV2640 引脚、分辨率、JPEG 质量和帧缓冲配置。
- `wifi_manager`：热点连接、超时、掉线重连和信号强度记录。
- `button`：GPIO 输入、上拉、消抖和重复触发保护。
- `capture_manager`：按批次拍摄 3～5 张照片。
- `upload_client`：HTTPS、鉴权、逐张上传、超时和重试。
- `device_status`：串口日志、LED 状态和心跳。
- `config_secrets`：SSID、密码、设备编号和密钥；不提交版本库。

### 5.2 按键逻辑

建议使用未被摄像头、PSRAM、Flash、USB/JTAG 占用的 GPIO；具体编号必须按开发板原理图确认，不能直接套用其他 ESP32-CAM 板卡的引脚。

- 输入模式：`INPUT_PULLUP`，按下时接地。
- 消抖时间：40～80 ms。
- 触发方式：确认一次有效按下后生成一个 `batchId`。
- 防重入：本批次未完成前忽略后续按键，或将其放入长度为 1 的队列。
- 可选交互：短按拍 3 张，长按拍 5 张；MVP 也可固定为配置值。

### 5.3 拍摄与上传状态机

```text
启动 → 初始化摄像头 → 连接热点 → 空闲
                                ↓ 按键
                         创建批次
                                ↓
                    拍摄 → 上传 → 释放帧缓冲
                       （循环 3～5 次）
                                ↓
                         提交批次结果
                                ↓
                              空闲
```

为避免内存不足，建议“拍一张、传一张、释放一张”，不要同时把 5 张原图全部保存在 RAM 中。若要求断网后补传，则需要增加 SD 卡或 LittleFS 缓存，并设置容量淘汰策略。

### 5.4 故障处理

- Wi-Fi 断开：指数退避重连，恢复后继续未完成任务。
- 上传失败：每张最多重试 3 次，例如 1 s、2 s、4 s。
- 服务端重复请求：使用 `batchId + sequence` 作为幂等键，重复上传不产生重复记录。
- 摄像头取帧失败：重新取帧一次；连续失败则重启摄像头驱动并记录错误。
- 看门狗：上传和拍照任务不得长期阻塞主循环。
- 时间：联网后同步 NTP；服务端时间作为最终可信时间。

## 6. 推荐实施顺序

### 阶段 A：确认硬件与接口（0.5 天）

1. 获取 ESP32-S3-CAM 的准确板型、摄像头引脚定义和原理图。
2. 与网站项目确认设备 API 基础地址、鉴权方式、字段和大小限制。
3. 确认电脑热点为 2.4 GHz，并开启互联网共享。
4. 确认采用 PlatformIO 还是 Arduino IDE；本计划默认优先使用 PlatformIO。

交付物：硬件清单、接口契约、可用 GPIO 和本机私密配置表。

### 阶段 B：固件工程与硬件自检（0.5～1 天）

1. 初始化固件工程、板型、串口和私密配置模板。
2. 完成 OV2640 初始化、单张 JPEG 拍摄和帧缓冲释放。
3. 完成按键输入、消抖和防止重复触发。
4. 完成热点连接、断线重连和 NTP 校时。

交付物：可稳定启动、联网、按键和拍照的固件基础版本。

### 阶段 C：上传与批次状态机（1～1.5 天）

1. 实现设备鉴权签名和 HTTPS 证书校验。
2. 实现批次创建、逐张上传和批次完成接口。
3. 实现 3～5 张连拍状态机，采用“拍一张、传一张、释放一张”。
4. 增加 LED/串口状态、超时、重试、幂等序号和异常恢复。
5. 在网站 API 尚未完成时使用本地 Mock 服务联调协议。

交付物：完整固件、配置示例、烧录说明和接口联调日志。

### 阶段 D：联调与验收（0.5～1 天）

1. 实机连续触发 20 个批次。
2. 测试 3 张和 5 张模式。
3. 测试热点断开、恢复、弱网、接口超时和重复请求。
4. 核对网页照片数量、顺序、时间和批次状态。
5. 整理部署、密钥轮换、日志定位和故障恢复说明。

预计本目录固件 MVP 工期：2～3 个工作日，前提是板型/引脚信息明确且设备 API 契约已确认。网站项目工期另行计算。

## 7. 验收标准

- 设备上电后 30 秒内连接电脑热点；网络恢复后可以自动重连。
- 单次有效按键只创建一个批次，并采集配置的 3～5 张照片。
- 正常网络下，按键后 30 秒内可在网页看到完整批次。
- 照片顺序正确、可预览，批次与设备编号可追溯。
- 单张失败不会导致整批静默丢失，网页能显示“部分失败”。
- 同一照片重试不会在数据库产生重复记录。
- 未登录用户不能查看照片；无效设备签名不能上传。
- 连续完成 20 个批次，设备无崩溃、无明显内存持续下降。

## 8. 第二阶段可选功能

- 网页远程触发拍照（MQTT 或设备长轮询）。
- SD 卡断网缓存与恢复补传。
- OTA 固件升级。
- 多设备管理、设备分组和在线状态看板。
- 图片水印（设备编号、采集时间）。
- 井盖状态识别或异常检测模型。
- 照片保留期、自动归档与清理策略。

## 9. 开工所需资料

开始本目录固件开发和联调前，需要以下资料：

1. ESP32-S3-CAM 的品牌、具体型号、购买链接或清晰的正反面照片。
2. 网站项目最终提供的 API 基础地址、设备编号、测试设备密钥和 CA 证书方案。
3. 电脑热点 SSID 和密码；仅写入本机私密配置文件。
4. 希望固定拍 3 张、5 张，还是采用“短按 3 张、长按 5 张”。
5. 使用 PlatformIO 还是 Arduino IDE；未指定时采用 PlatformIO。
